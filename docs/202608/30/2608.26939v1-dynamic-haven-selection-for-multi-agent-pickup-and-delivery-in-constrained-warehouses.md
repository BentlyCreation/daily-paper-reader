## 摘要
空间高效的仓库布局通常包含单智能体宽度的通道和死胡同工作站，在那里机器人几乎没有可以等待而不阻挡他人的地方。在此类受限布局的多智能体取送货（MAPD）中，机器人必须接受在线取送货任务，同时保留称为Haven的受保护等待位置。安全Haven撤退规划器（SHARP）引入了一种机制，为每个已承诺的任务路径扩展一条经过验证的撤退路径，回到智能体专用的初始Haven，但固定Haven的承诺可能会在交付后将智能体送往远处的Haven。我们提出A-sharp（自适应SHARP），它在任务分配时改变智能体的撤退目标。简单的切换可能导致两个智能体依赖同一个等待位置，或让另一条已承诺路径穿过仍被占用或保留的位置。A-sharp通过候选Haven的可用性测试和待释放规则来防止这些失败，待释放规则在智能体离开前保持先前Haven受保护。在显式Haven结构和安全间隔路径规划（SIPP）假设下，我们证明了不变量保持和有限释放完备性：任何有限释放序列中的每个任务都能在有限时间内完成交付。在四个地图上的14,400个成对的地图-智能体数量-速率-种子案例中，共进行72,000次运行，SHARP和A-sharp各自完成了其对应的14,400次运行。对于完工时间（最终交付时间），在所有138个Haven数量多于智能体数量的配置上，使用预先指定的配对比较和Holm校正，发现A-sharp在107个配置中显著优于SHARP，且从未显著差于SHARP；在测试的树状地图上，中位数减少16.7%。

## Abstract
Space-efficient warehouse layouts often contain single-agent-width aisles and dead-end workstations where robots have few places to wait without blocking others. In Multi-Agent Pickup and Delivery (MAPD) on such constrained layouts, robots must accept online pickup-delivery tasks while preserving protected waiting locations called Havens. The Safe HAven Retreat Planner (SHARP) introduced a mechanism that extends each committed task path with a validated retreat to the agent's dedicated initial Haven, but fixed-Haven commitments can send agents toward distant Havens after deliveries. We present A-sharp (Adaptive SHARP), which changes an agent's retreat target at task assignment time. A naive switch can cause two agents to rely on the same waiting location or let another committed path pass through a location that is still occupied or reserved. A-sharp prevents these failures with an availability test for candidate Havens and a pending-release rule that keeps the previous Haven protected until the agent departs. Under explicit Haven-structure and Safe Interval Path Planning (SIPP) assumptions, we prove invariant preservation and finite-release completeness: every task in any finite release sequence is delivered in finite time. Across 72,000 runs on 14,400 paired map-agent-count-rate-seed cases over four maps, both SHARP and A-sharp complete their respective 14,400 runs. For makespan (final delivery time), a prespecified paired comparison with Holm correction over all 138 configurations with more Havens than agents finds A-sharp significantly better in 107 configurations and never significantly worse than SHARP; on the tested tree map, the median reduction is 16.7%.

- **研究背景**：在自动化仓库等物流系统中，多智能体取送货（Multi-Agent Pickup and Delivery, MAPD）问题要求机器人在线接受任务并规划无碰撞路径。在空间高效的仓库布局中，常存在**单智能体宽度的通道**和**死胡同式工作站**，机器人几乎没有可等待而不会阻塞他人的位置。经典MAPD方法（如基于Token Passing的TP、基于优先继承回溯的PIBT）依赖良好结构假设（如well-formedness、双连通性），但这些假设在密集仓库布局中可能不成立。
- **核心问题**：已有的安全Haven撤退规划器（SHARP）为每一条已承诺任务路径配套一条经过验证的撤退路径，回到智能体**专用的初始Haven**。这种固定Haven的承诺可能在交付完成后把智能体派往远处的Haven，造成不必要的长距离绕行与局部拥堵。能否在任务分配时**动态改变撤退目标**，同时保持安全性？这一问题的难点在于：简易切换会导致两个智能体依赖同一等待位置，或让另一条已承诺路径穿过仍被占用或保留的位置。
- **整体含义**：本文提出A♯（Adaptive SHARP），一种动态Haven选择方法，在保持安全撤退规划结构的前提下，通过所有权转移协议实现撤退目标的在线更新，并证明其满足有限释放完备性——任何有限任务序列中的所有任务都能在有限时间内完成交付。该研究填补了固定Haven撤退机制无法动态调整的空白。

## 2. 论文提出的方法论：核心思想、关键技术细节、算法流程

### 2.1 核心思想

A♯的核心是**以原子方式**将"未来路径预留"与"排他性Haven所有权"同步更新，通过可用性检查（availability test）和待释放规则（pending-release rule）来保证动态Haven切换的安全性。

### 2.2 关键定义与机制

- **Haven结构条件**（Definition 2）：(1) 任务支撑核心 F = V∖H 上的诱导子图 G[F] 连通；(2) 每个Haven至少有一个邻居在F中；(3) 所有任务端点都位于F中。这保证任务区域在移除Haven后仍连通，且每个Haven可从连通区域进入。
- **独占集 X_t(a) ⊆ H**：记录为智能体a保护的Haven顶点集合，始终包含当前Haven η_t(a)。转移期间可能临时包含仍被占据的旧Haven。
- **可用Haven定义**（Definition 3）：候选Haven h对智能体a在时间t可用，当且仅当：(1) h不在任何其他智能体的独占集中；(2) 没有其他智能体对h在t′ ≥ t的任何时间有已提交的预留。
- **待释放规则**：当智能体从仍占用的旧Haven切换时，旧Haven继续保留在独占集中，直到该智能体实际离开该Haven。这防止了其他智能体规划通过一个物理上仍被占用的顶点。
- **原子更新**：新路径预留、η_t(a)和X_t(a)的更新作为一个状态转换原子完成，不允许其他分配或规划步骤观察到只更新了其中一部分的中间状态。

### 2.3 三种典型失败教训

1. **过早释放被占用的旧Haven**：所有权视图和执行视图产生分歧，其他智能体可能规划通过物理上仍被占用的顶点。
2. **选择被未来预留的Haven**：仅检查所有权会忽视其他智能体的时空预留冲突。
3. **陈旧自预留残留**：接受新任务后，旧的自预留必须被原子替换，否则会导致自身冲突或阻塞后续智能体。

### 2.4 算法流程（Algorithm 1，A♯分配循环）

1. **任务加入**：将t时刻释放的任务加入待处理集Q。
2. **候选智能体筛选**：I = 空闲或撤退中且无待释放旧Haven的智能体。
3. **循环分配**：当Q和I均非空时重复：
   - 为每个智能体a选择最近的待处理任务τ（按到取货点的距离）。
   - 计算a的可用Haven集合 H_a(t)，选择距离交付点最近的h。
   - 调用PlanFullPath(a, τ, h, t, R, X_t, T_max)验证完整路径（当前位置→取货→交付→Haven），三段SIPP拼接。
   - 选择全局最优候选（最小取货距离）提交。
   - 提交时：保留t时刻预留，删除t′>t的旧预留，插入新路径条目，更新η_t(a)和X_t(a)，按需设置待释放旧Haven。
4. **执行一步**：按已提交预留执行一个时间步的移动。
5. **清理**：交付后标记为撤退中，到达Haven且无任务标记为空闲；智能体离开旧Haven后将其从独占集中移除。

### 2.5 理论保证

- **命题1**（动态Haven更新保持独占集不变量）：注入性、独占集不相交、待释放Haven数量约束均保持。
- **引理1**（单时间步不变量保持）：分配阶段、执行阶段、清理阶段后所有执行与预留不变量保持。
- **引理2**（静止状态下规划成功）：在静止配置中，对任何待处理任务、任何智能体、任何可用Haven，PlanFullPath必然成功。
- **定理1**（有限释放完备性）：在所有假设下，A♯能在有限时间内交付所有释放任务。证明思路：假设有任务永远未完成→最终静止→引理2迫使新的成功承诺发生→矛盾。
